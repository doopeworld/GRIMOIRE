Plan when it is next: `--proj native` for safetensors, like GGUF: keep each tensor's file format. NVFP4 as a native block type in the
GGUF framework (`B70_NATIVE_GGUF`): llama.cpp's type 40 layout, 64 values in 36 bytes, four UE4M3 scales per 16 values, in each
16-value sub-block the low nibble of byte j is value j and the high nibble value j+8 (ggml-quants.c `dequantize_row_nvfp4`). GGUF has no
per-tensor scale, so the safetensors global scale becomes a per-row f32 factor applied to the output (merged gate/up keep one each).
Per-channel FP8 should map onto `--proj fp8` row scales without a second rounding; check whether the loader keeps the file's
bytes and scales or re-rounds. Measure: top-1 against the BF16 original
(`tools/bench/accuracy`) and decode speed against `--proj int8` on Qwen3.8-27B-NVFP4.
