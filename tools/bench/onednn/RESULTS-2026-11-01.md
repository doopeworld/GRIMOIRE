# Native GGUF, oneDNN W8A8 and device MTP drafts

Measurements on one Arc Pro B70, 2026-10-31 and 2026-11-01. GPU1 was not used.
These options default off. The completed v1.10.2 release is a separate checkpoint;
the full unfinished engine scope is in [the roadmap](../../../ROADMAP-2026-10-31.md).

## Native grouped experts

Ornith-1.5-35B Q4_K_M GGUF, `--proj native`, eight slots, context 32000.
Both settings use the same corrected candidate binary. llama-benchy 0.4.0,
pp4096/tg128, two runs. Rates below are total decode tokens/s.

| Users | Native grouped OFF | Native grouped ON |
|---:|---:|---:|
| 1 | 155.58 ± 0.01 | 156.10 ± 0.05 |
| 2 | 95.76 ± 0.08 | 160.71 ± 0.32 |
| 4 | 115.12 ± 0.01 | 247.80 ± 1.38 |
| 8 | 133.74 ± 0.08 | 364.82 ± 0.73 |

`GRIMOIRE_MOE_NATIVE_SMALLM=1` uses device expert/count/offset tables with native
Q4_K/Q5_K/Q6_K/Q8_0/IQ4_XS/IQ4_NL DPAS for supported batches of 2..16 rows.
It preserves saved weight blocks. Exact verification and unsupported shapes retain
their old paths. Gate/up and down operate in the existing scratch allocation.

The independent FP64 oracle covers six formats, M=2/3/8/9/16, shuffled/ragged experts,
empty and padded table entries, output guards, dense fallback, and real Ornith matrix
dimensions: 32 cases pass. The integrated first version failed native dense argument
binding despite passing standalone tests; typed dense/grouped captures fixed that
integration failure. The exact compiler metadata cause was not proven by the standalone test.

Single-user coding 2/2 and coherence pass in both modes. Concurrent coding is 6/8 in
both modes; generated answers differ. This is not a claim of universal coding success
or token parity. Logs: `gnm-{off,on}-r1-1031.*`.

The combined 11-01 build measured pp4096 7863.40 / tg128 357.95 total at eight users
(one run), with coherence and Paris passing. Its concurrent coding sample passed 5/8;
this does not improve the earlier quality limitation. Keep the option experimental.
Logs: `engine-orn-native-1101.*`.

## Optional oneDNN activation quantization

Qwen3.8-27B-FP8 loaded as INT8, one sequence slot, context 8192, no MTP.
Saved weights do not change. Activations use per-row dynamic symmetric INT8 scales
before the oneDNN S8×S8 matmul, with FP32 outputs. Small decode/verification calls retain
their existing arithmetic.

| `GRIMOIRE_ONEDNN_W8A8` | Additional selection rule | pp4096 tok/s | Top-1 vs BF16 | Mean cosine | Mean KL |
|---|---|---:|---:|---:|---:|
| `0` (default) | BF16 activations | 2077.09 ± 2.19 | 98.4% | 0.9981 | 0.0188 |
| `1` | All eligible projections | 2909.32 ± 2.99 | 93.8% | 0.9865 | 0.1254 |
| `2` | N ≥ 32768 or K ≥ 16384 | Not timed | 95.7% | 0.9928 | 0.0563 |
| `3` | N ≥ 32768 | 2527.06 ± 46.60 | 97.7% | 0.9966 | 0.0402 |

All quantized cases additionally require INT8 weights, M ≥ 32, N ≥ 256, and K divisible
by 64. Selection uses local matrix dimensions; TP sharding can make a conservative
mode select no weights. Mode 3 keeps Qwen's attention and FFN down projections at BF16
activation precision. Do not infer its speed or quality on another architecture from
this one measurement.

Accuracy uses 256 independent prompt prefixes from the opening of “A Scandal in Bohemia”,
with the existing original-BF16 CPU reference and the same token IDs. This exercises
prompt GEMMs, unlike the original per-token decode scorer. All modes are bit-identical
to mode 0 for the first 31 prefixes. Across later prefixes, mode 3 agrees with mode 0
at 223/225 top-1 positions. This limited corpus is not a general task-quality benchmark.
The more accurate mode 3 still loses two reference matches; none of the modes is a
fidelity-preserving replacement for the default.

The whole-call GEMM oracle includes activation quantization, rotating cold weights,
FP64 reference arithmetic, tiny values, zero rows, outliers, accumulation and padded tails.
Correctly rounded per-row scale/reciprocal computation resolved the initial tie mismatch.
Representative W8A16 -> W8A8 times: 512×34816×5120 = 1.145 -> 0.742 ms;
2048×5120×17408 = 2.257 -> 1.506 ms. Small 33×256×512 regresses, 0.026 -> 0.047 ms.
The option stays experimental rather than imposing that tradeoff on every shape.

Mode 1 passed coding 2/2 and coherence; decode stayed at 20.6 tok/s. Mode 3's combined
build also passed coding 2/2, prose 2/2 and coherence, with coding TTFT 0.88 s versus the baseline 1.03 s and
decode still 20.6 tok/s. The mode 0/1 speed measurements are from 10-31; mode 3 and the
prefix comparisons are from 11-01. Logs: `engine-w8wide-1101.*`, `w8serve-{off,on}-1031.*`,
`w8score-reference-{off,on,large,wide}-1101.out`, `w8score-prefix-check-1101.out`.

The JIT diagnostic initially segfaulted in SYCL's persistent cache writer, then the driver
reset the compute engine. The fault address resolves to `PersistentDeviceCodeCache::putItemToDisc`
in matching builder/runtime libraries. No process or render holder remained and PCIe counters
stayed zero. A guarded numerical recovery probe passed all 32 cases. Disabling
`SYCL_CACHE_PERSISTENT` for that JIT diagnostic allowed all four full scoring runs to finish
without new driver errors. The normal production AOT configuration was not changed.

## MTP proposal history on the device

`GRIMOIRE_MTP_GPU_DRAFT=1` keeps batched proposals in device history between draft depths,
with one final readback. Argmax writes each depth directly and the next depth embeds that
history in place. Rows that drop out are compacted without a host proposal readback.
The option applies to single-GPU batched dense MTP heads; n=1, MoE heads and TP/PP keep
their existing paths. Batched drafter allocations are also freed on release/reload.

Qwen GPTQ-Int4-MTP-BF16, eight slots, context 16384, K=6, draft vocabulary 65536.
Both modes use the same revised binary and timing instrumentation. Three benchmark runs:

| Users | Device history OFF | Device history ON |
|---:|---:|---:|
| 2 | 96.14 ± 7.11 | 105.99 ± 5.66 |
| 4 | 178.62 ± 4.46 | 184.10 ± 5.00 |

Variance overlaps; this is not a strong general speed claim. Verification still dominates
the profile at about 43–46 ms per step, compared with roughly 4.5–7 ms for drafting.
An earlier version with intermediate device copies lacked a clear gain and was revised.

Both modes pass 10 coding answers and coherence. All 38 responses match in text, token
count and finish reason: two single coding answers, eight concurrent coding answers and
28 requests with uneven token budgets. The latter exercise shrinking active rows and
fallbacks at 2/4/8 users. Logs: `mtpv2-{0,1}-1101.*`.

The old synthetic token-equality test also fails on the unchanged engine in its MoE
scheduled path, after seven dense/hybrid cases pass. The revised option passes those
same cases, including forced accepted drafts, then reaches the same separate MoE gate.
The MoE head does not use device draft history. Exact-verification settings did not make
the whole GPU suite pass either. Do not report this as a clean ten-case synthetic pass;
its GPU arithmetic/reference assumptions remain a separate open issue.

## DFlash2 with native GGUF

The released v1.10.2 image loads and actually drafts with Qwen UD-Q4_K_XL native GGUF and
the Qwen DFlash2 sidecar. Coding 2/2, concurrent coding 8/8 and coherence pass.
pp4096 = 1979 tok/s; tg128 = 51.61 single-user and 73.23 total at four users.
Native MTP is faster on this configuration (59.4 / 141.6), so DFlash2 is not recommended
as a speed win there. A 64-token fixture matches plain greedy in exact-verification mode;
the fast mode first differs at token 36. These fixture results do not establish universal
token parity. Logs: `df-gguf-code-1031r.*` and `df-gguf-*-1031.log`.

## Combined native Qwen GGUF + MTP

The combined 11-01 CLI/server build with Qwen UD-Q4_K_XL, native projections, K=6,
draft vocabulary 65536, eight slots and device drafts enabled passed single coding 2/2,
concurrent coding 8/8, coherence and the Paris check. One llama-benchy run measured
pp4096/tg128 2069.15/51.45 for one user and 1942.25/136.24 total for four users.
Different acceptance samples and the single run limit comparisons with earlier rates.
GPU0 reported no new link errors. Logs: `engine-qg-1101.*`.
