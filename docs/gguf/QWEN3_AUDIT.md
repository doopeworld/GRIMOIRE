# Standard Qwen3 and Qwen3-MoE GGUF audit

Scope: `qwen3` Qwen/Qwen3-8B-GGUF and `qwen3moe` unsloth/Qwen3-Coder-30B-A3B-Instruct-GGUF. The evidence below uses the checked-in HF forwards, their checked-in configs, the pinned llama.cpp converter, and both real GGUF header slices. Host tests establish parsing, tensor mapping, tokenizer IDs, and reference arithmetic. SYCL compilation and inference still require the B70.

The device `dense` and `moe` matrix fixtures previously used Qwen3 model types while initializing norm weights to zero, and the MoE fixture included a shared expert. Those conventions matched Qwen3.5, not real Qwen3 (`tools/mini_model.hpp:389-418,868-904`). They now initialize norms to one and omit the shared expert. The host GGUF test checks a deliberately non-unit norm weight against the HF formula, a 128-expert top-eight reference distribution, both real config/header pairs, a tied output, a mixed dense/routed MoE pattern, and tensor mappings (`tests/test_gguf_qwen3.cpp`). A green host suite cannot establish B70 kernel correctness.

Follow-up from B70 Qwen3-8B validation: sequential decode matched llama.cpp, but batched prefill differed. The generic batched Q/K norm plus RoPE entry points in `src/kernels.hpp` defaulted to offset 1 even after `build()` installed offset 0; the BF16 Q/K prefill kernel and quantized/MoE prefill norms in `src/prefill.cpp` also used `1+w` directly. They now use the installed convention. `tests/test_qwen3_prefill_math.cpp` checks the scalar math and M>1 layout used by prefill against the independent Qwen3 decode formula at Q32/KV8/D128, and proves the former `1+w` convention is detected. The SYCL kernels and end-to-end prefill self-check still need B70 validation.

## GGUF conversion and adapter

The pinned converter's `Qwen3Model` inherits `Qwen2Model` (`.ref/qwen_conversion.py:160-163`) and `Qwen3MoeModel` inherits `Qwen2MoeModel` (`:259-262`). The latter splits HF fused `gate_up_proj` along its output dimension into GGUF gate/up expert tensors (`:105-117`). The Qwen3 reranker override delegates ordinary causal-LM tensors to its parent (`:245-256`). Inspection of pinned `conversion/base.py` `ModelBase.modify_tensors` (commit `711780ffc75b`, lines 844-904) found name mapping and optional fusion, and **no Q/K row permutation** for these architectures. The LLAMA converter's Q/K permutation is architecture-specific. The adapter therefore maps Q and K rows directly; a synthetic numbered Q matrix pins this (`tests/test_gguf_qwen3.cpp`). Norms also have no converter shift.

`src/gguf_qwen35.cpp:212-332` synthesizes the standard root `qwen3`/`qwen3_moe` config from GGUF metadata and checks it against an optional HF sidecar before feeding the existing parser (`src/qwen35_loader.cpp:180-192`). It reads block count, embedding and FFN width, Q/KV head counts, key/value widths, context, theta, epsilon, and the MoE counts/width. It rejects inconsistent geometry, shared-expert metadata, and doubled Q projection rows. The GGUF layer pattern is encoded canonically as step 1 plus a list of dense layers; sidecar comparison accepts an equivalent `decoder_sparse_step` pattern. `src/gguf_qwen35.cpp:334-451` maps token embeddings, output/head and output norm; per-block attention norms and Q/K/V/O, per-head Q/K norms, FFN norm, dense gate/up/down, router, and 3-D expert gate/up/down split into individual expert references. Qwen3 uses `model.` names and no inverse norm transform. The existing raw-row uploader recognizes native GGUF tensor references (`src/gguf_qwen35.cpp:452-471`), so `--proj native` takes the same direct quantized path.

Real header cross-checks use `GGUFFile::open(path, err, true)` and the complete checked-in HF configs. Qwen3-8B is 36 layers, H4096, Q32/KV8, head 128, dense width 12288, theta `1e6`, explicit output. Coder is 48 layers, H2048, Q32/KV4, head 128, 128/top-8 experts of width 768, theta `1e7`, explicit output, and all layers routed. **The Coder GGUF records `feed_forward_length=5472`; its HF config records `intermediate_size=6144`.** Since step 1 and `mlp_only_layers=[]` route every layer, neither dense width is executed. The test asserts both actual values, and sidecar checking exempts only this unused field. A future GGUF with dense MoE layers needs its actual dense width validated against its tensor shapes before execution.

Both headers declare `tokenizer.ggml.model=gpt2`, `tokenizer.ggml.pre=qwen2`. The exact pinned qwen2 regex in llama.cpp `src/llama-vocab.cpp:383-391` uses `\p{L}` rather than Qwen3.5's `\p{L}\p{M}`. `src/tokenizer.cpp:196-209,421-433,1615-1730` recognizes the pre name, distinguishes Unicode marks from letters, and applies the HF tokenizer JSON's NFC normalizer. Unicode 13 mark, decomposition, combining-class and composition tables are generated from Python 3.9.6 `unicodedata` by `tools/gen_qwen2_unicode.py`. The golden fixture `tests/tokenizer_golden/qwen3_hf_golden.json` contains exact IDs from the pinned Qwen3-8B HF tokenizer on multilingual text, combining marks, code, and whitespace. The optional whole-vocabulary check compares all shared IDs and merge ranks; GGUF pads beyond the HF vocabulary with control/unused entries. Coder omits GGUF BOS metadata, so sidecar validation treats that field as optional (`src/qwen35_loader.cpp:248-261`).

## B70 verification gate

1. Compile the full SYCL engine, bridges and tests on the B70; run `make test`, the `dense` and `moe` `test_model_matrix` cells, and the native-GGUF device test. Check the capability banner for plain `w` norms, full RoPE, correct heads, no attention gate, and no shared expert.
2. Run Qwen3-8B BF16 safetensors and a **lossless** GGUF of those same tensors through identical prompts and compare token IDs exactly, with distinct prompt continuations. The available official Q8_0 and Q4_K_M files are quantized, so exact BF16 token identity is not their gate.
3. For the official Q8_0 and Q4_K_M files, compare prefill and decode logits against llama.cpp on the **same GGUF** using KL divergence across short and long prompts, then inspect generated text. Record first divergent token and layer-level Q/K norm, RoPE, attention and FFN probes if KL is large. Repeat with `--proj native` and a dequantizing projection mode; exercise MoE Coder top-8 routing separately.
