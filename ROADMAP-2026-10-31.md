## Current execution

**2026-11-05: v1.10.4 PUBLISHED (315167c); read [HANDOFF-2026-11-05.md](HANDOFF-2026-11-05.md) first.** It closes the 11-04
MXFP4-vs-INT4 decode gap (MXFP4 small-M kernels: Qwen3.8-27B MXFP4 + MTP one user +26%), makes two GPUs faster than one for
4-bit prompts (GPTQ pp4096 3,093 vs 2,062), adds the peer-partial two-card exchange (lossless, +2.8%) and ships the CPU-expert
pool fix. INT4 prompts vs MXFP4: only ~2% (dequant passes equal) -- not pursued. Open: two GPUs at 4 users (139 vs 177 on one
card), INT4 / GGUF verify split plans, burst admission for long prompts, the B580 numbers.
Numbers: [RESULTS-2026-11-02.md](tools/bench/onednn/RESULTS-2026-11-02.md).

Results from 11-02: the narrow split-K plan for 9-16 row INT4 verify is **dropped**: the 47% figure compared 128-register
copies; shipping 256-register kernels already match it. The kernel-name collision on GGUF decode looks harmless (the main binary's image
wins and its only caller is in the main binary). Ornith's concurrent coding failures are a model mistake: the same prompt fails alone, in both modes, with
byte-identical text. The CPU-expert pool's slowdown on a busy host is **fixed on `cpu-pool-late-workers-1102`**: Flash-Next served
3.91 -> 24.06 tok/s with builds running, same answers, no quiet-machine cost. That branch also leaves one card's decode thread free and
groups native GGUF experts by default. Its final code still needs its build, Flash-Next check and regression, then merge; it reaches the next image, not v1.10.3.
